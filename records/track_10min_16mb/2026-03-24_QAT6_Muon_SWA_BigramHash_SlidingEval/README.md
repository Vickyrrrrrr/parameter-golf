# QAT6 + Muon + SWA + BigramHash + Sliding Eval

## Summary

This submission copy starts from the current root `train_gpt.py` harness and adds:

- int6 QAT with `QAT_START=200`
- LeakyReLU^2 MLPs, orthogonal linear init, and a trainable low-rank `BigramHashHead`
- Muon for matrix parameters and AdamW for scalar parameters
- SWA with `SWA_START_FRAC=0.50` and `SWA_FREQ=50`
- sliding-window validation with `EVAL_SEQ=2048` and `EVAL_STRIDE=64`
- longer training context with `TRAIN_SEQ_LEN=2048` and `TRAIN_BATCH_TOKENS=786432`
- `model.bin` export using mixed fp16/int6 weights with `zstd` when available, otherwise `zlib`
- a pre-training artifact budget estimate and a hard `16,000,000` byte submission check

## Notes

- `model.bin` is generated by the training script during export.
- The literal scalar-only BigramHash bias from the planning prompt would cancel out inside softmax, so this implementation uses a low-rank hashed logit-bias head instead.
- The default BigramHash size/rank is intentionally kept modest so the artifact stays under the 16,000,000-byte cap even when `zstandard` is unavailable and export falls back to `zlib`.
- I could not populate the result table in this workspace because the FineWeb shards and a runnable Python command were not available locally.
